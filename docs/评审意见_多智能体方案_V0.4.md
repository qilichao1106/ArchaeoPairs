## 一、总体评价

V0.4 在 V0.3 基础上做了一次**价值正确的大重构**：按图片类型三线路分流，"单器物不分割、多器物才走 SAM"，从机制上消除了 V0.2 中"单器物也进 S6 分割"的算力浪费与 rule_b 合并路径混乱；明确移除跨图合并、成本帽/熔断，范围收敛良好；器物号两步归一与 §2.2.4 反例（T18④:7 / H83①:35 / ⑤:40 / C5.1H146:1 / 406号墓）与上一轮代码修复结论一致，实证口径 §2.2.5 完全可复现。**文档数据纪律强、架构立意好。**

但作为"以图分类为唯一路由依据"的新架构，本轮评审聚焦其**新引入 / 未能闭合**的三个结构性问题：① S2 单/多/丢弃判定的可判定性（尤其 28% 零 XML 信号图 + rule_b 序号歧义）；② S1 图注关联退化为"仅后紧邻"导致的组合图回归；③ no-note 图 E005 误报与链②反推能力之间的口径矛盾。这些问题直接决定三线路的**分流正确率**与**吞吐/复核对冲**，属 P0/P1。

## 三、维度 A｜分类体系自洽性（内部一致性）

- **A1.【P2】"五分类"称谓与 6 值枚举不符。** §3.2/§1.6/§4.2 的 image_type 实际枚举 6 个：`single_line / multi_line / plate_artifact / multi_plate / plate_scene / discarded`；但全篇称"五分类/输出 5 类/5 类决策路由"。`plate_scene` 与"其它"的关系未界定（plate_scene 实为"其它"的视觉肯否特例，却单列为并列枚举值）。
- **A2.【P2】case_type（S5 输出）混入非 S5 产出的单器物类型。** §4.5.1 表格把 `single_line`、`single_plate`、`discarded` 列为 case_type；但它们分别是 S2 路由到 S7 / 丢弃的结果，**从不经过 S5**。case_type 枚举与 S2 职责、image_type 语义重叠。
- **A3.【P2】单器物类型三套命名漂移。** 同一语义三种命名：`single_plate`（case_type）vs `plate_artifact`（image_type）vs `CLASSIFIED_PLATE`（状态机）；`single_line`（case_type）=`single_line`（image_type）≠`CLASSIFIED_SINGLE_LINE`（状态机）。建议统一为单一枚举来源（§1.6），状态机状态与 case_type 分离命名。

## 四、维度 B｜S2 单 / 多 / 丢弃可判定性（三线路分流核心，优先级最高）

> 三线路的正确性**100% 依赖 S2 分流正确**。但实测表明其可判定性存在结构性缺口。

- **B1.【P0】28% 的图进入 S2 时零 XML 信号，分流纯靠 VLM 视觉。** 实测 4,327 张（占全量 28%）满足 `图题在 ∧ 无图注 ∧ 图题无器物号`，单/多/丢弃判断无任何 XML 依据。§4.2 判定依据写"按 XML 器物号个数细化"，但该类图 XML 器物号个数恒为 0，**文档未给出无 XML 信号时 VLM 的视觉划定规则**（判别单器物物轮廓个数？视图数?）。
  建议：明确在此类图上的视觉量化规则 + 置信阈值；低置信判 `discarded` 与否走 §4.2 决策表（"无可辨识主体→discarded"），单/多低置信 → 报警（而非硬猜），并给出占比预算。
- **B2.【P0】"图内序号个数"不能区分 single_line 与 multi_line（rule_b 序号歧义）。** rule_b 单器物多视图（如"舟腹部 序号1 / 舟圈足 序号2"）图内 ≥2 序号却属 **1** 件器物；§4.2 判定依据"图内仅有 1 个器物序号 → 单器物 / ≥2 个 → 多器物"对 rule_b 会**误判为多器物**。对无 XML 信号图，VLM 无法先验知道多个序号是同器视图还是异器→若误送多器物线路则因链①缺失触发 seq_missing→E005 误报（明明是可解的 rule_b）。§5.7 多视图归组只在多器物线路 S9 后处理，**未前置到 S2 分流**，时序缺口。
  建议：把"多视图/同器归组"信号（视图名语义、共享基准线、XML 单器物号）前置为 S2 判定的一级证据，或至少定义"序号个数歧义→先按多器物进入、S9 归组校验回退"的确定性规则，避免无约定状态。
- **B3.【P1】彩板 multi_plate / plate_artifact 亦纯视觉，负载大。** examples 全量图题含图版/圖版/拓片约 **3,000+ 张**（赵廷隐 656、栎阳城中 504、栎阳城上 294、栎阳城下 227）。S7 单器物路径负载与多器物彩图误判面需预置（单器物彩图误判为多→丢弃丢数据；多判单→错误 Pair）。

## 五、维度 C｜S1 图注关联回归风险

- **C1.【P1】§2.4/§4.1 主链解析器退化为"仅后紧邻"。** 原句"遍历文档序将 figure 与其**后**紧邻的 figure-note para 关联"。实测存在 **112 个"同题多 figure"组合图组（涉 243 figure）**：瓦子坪"图四 2004CWW M11器物组合 x2"、长沙青振"圖三三… x3"、郑州商城 43 组、大兴东庄营 14 组、赵廷隐 14 组等。仅后紧邻会把图注只归给组内某一张，其余组员（尤其比例尺条图）错配/漏配——**正是上一轮 V0.2 代码已修复、并实测纠正的组合图缺陷（image9/image10）**，V0.4 未继承该修复，属**回归**。
  建议：§4.1 补"同图号连续 figure 分组 + 图注前置回溯 + 组内最大面积归属 + 相邻 figure-title 恢复"，或显式声明上游契约保证"一 figure 一 figure-note、无组合图"（当前 examples 并不满足）。
- **C2.【P2】无 caption 的 figure 从相邻 `para role="figure-title"` 恢复图题**（V0.2 已修复的 isolates e.g. 图版六三条带）未在 V0.4 §4.1 体现；对 6,636 张 caption 缺失图的"是否可恢复"无策略。

## 六、维度 D｜降级矩阵 vs no-note 反推矛盾

- **D1.【P1】seq_missing（E005）与链②"图引用反推 seq_id"口径矛盾。** §4.5.1：seq_missing="图注无序号列表（含图注缺失）→ 无法建立 seq_id↔artifact_id → E005"。但 §3.6/§4.3/§4.7.2 承认链②可用"图引用反推 seq_id"（"（图三四，3）"→seq 3→artifact）。二者冲突：**no-note multi-line 若正文有图引用，本可按链②反推绑定，却被 seq_missing 一律送入 E005 复核**。在无图注率 48.8% 的现实中，这会造成大量"本可自动解"的图被空送复核。
  建议：把图引用反推作为 no-note multi-line 的**主流（链②绑定时不入 E005）**，seq_missing 仅当"链①缺失 ∧ 链②无反推证据 ∧ 需图面匹配"触发。
- **D2.【P0 吞吐】零信号多器物图大概率集中触发 E005 → 海量 PENDING_REVIEW。** 结合 B1（4,327 零信号图）与 D1：多器物线路中 no-note 且链②无可反推的图，将成批转复核。§4.3.3 "高 figure-note 缺失率报告链②反推专项（D4）"仅一句、无算法；§9.3 "PENDING_REVIEW 阈值分报告自适应"是**事后兜底而非事前降量**。建议给出链②反推对 no-note 图的覆盖率测算，并设"复核率上限消化预算"。

## 七、维度 E｜自包含性 / 文档完整性

- **E1.【P2】外部编号未定义，与"文档自完备/去除历史痕迹"声明冲突。** §1.4"评审 N1 的 B 计划"、§4.3.3"(D4)"、§9.4"(O10)"、§10.3"(O5)(O7)"——N/D/O 分类体系文中未给出，读者无法理解对应设计动机。
- **E2.【P2】图题兜底"二者一致时增强，不一致→？"缺仲裁。** §1.4 链Ⅰ"图注优先、图题兜底、二者一致时增强"；但图注与图题**冲突**（同图不同器物号、或多对一）时无处理规则（报警？图注优先？）。

## 八、维度 F｜资源与吞吐

- **F1.【P2】§9.2 单号把"16,124 图 × 最坏 12 次 = 193,488"当典型预算。** 三线路下单器物线路无 SAM、少 OCR，是**低成本路径**；若按线路混合权重重算平均调用次数会显著低于 12。文档以最坏当典型，资源预算失真或过度。建议按线路分布给出期望调用数与 GPU 需求区间。
