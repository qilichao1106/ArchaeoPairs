## 〇、总体评价

V0.5.1 在 V0.5 编排拓扑（单器物不经 S9、S6→S8→S9 重排、S10 两级分流）基础上做了一次**方向正确的一致性收敛**：状态机按附录 B 拓扑重排、rule_b 归组前移至 S7、弱链①与 E005 边界仲裁（图题恰 1 号降级 / ≥2 号报警）、错误码与术语表口径统一，历次评审的 B2（rule_b 序号歧义前置消解）、C1（S1 组合图兼容层）两条 P0/P1 均已实质闭合。**架构骨架已具备可落地性。**

但本轮核对发现一类**新的结构性问题：文档—代码漂移**。V0.5.1 修订历史声称"删除 SEG_DIAGNOSED、新增 MULTI_LINE_SKIPPED 与 FigureStatus 枚举、case_type 剔除 image_type 成员、修复 DDL 残损"，**但仓库代码与 DDL 均未同步**（详见第八节核对表）。文档描述的是"目标态"而非"当前实现"，而文档未做任何标注——读者（含后续开发者）无法区分设计意图与已落地事实，这正是 V0.4 评审曾指出的"文档自完备性"问题在新形态下的复发。此外，§6.5.1 DDL 在 docx 中仍为残损文本，"修复 DDL 残损"的修订声明与实际不符。

## 一、架构与编排合理性

**通过项：**
1. 模块划分清晰：S1–S10 职责单一，确定性节点（S1/S2/S5/S7/S8/S10）与概率节点（S6/S9）边界明确，编排层只做流程控制（`graph.py` 与业务分离）。
2. 回环收敛有界：S9 修正回环 guard 为 `iteration<3`，且"连续两轮无改善 → PENDING_REVIEW"双保险；状态机明确"回跳仅由 S9 诊断驱动，不存在无条件重试回跳"，无死循环风险。
3. 逃生舱机制完备：PENDING_REVIEW + Label Studio 人工复核、批次暂停阈值、Feature Flag 独立开关、MULTI_LINE_SKIPPED 可恢复归档、服务级降级挂起（不失败）。
4. checkpointer 幂等键（thread_id 不含 iteration）与 claim 机制（SELECT FOR UPDATE SKIP LOCKED）职责分工清晰。

**问题：**
- **A1.【P1】orientation_err 的路由口径文档与代码不一致。** §3.4.3 路由表把 orientation_err 并入第一行（`含 under_seg/over_seg/mask_incomplete/scale_mismatch/orientation_err 且 iteration<3 → s6_segment`），但代码 `routing.py` 的 `_MASK_DEFECTS = {under_seg, over_seg, mask_incomplete, scale_mismatch}` **不含 orientation_err**——若 S9 仅诊断出 orientation_err，代码落入兜底分支直接 `bridge_review`（转人工），文档预期"旋转校正后重分割"。二者行为相反，须择一对齐。
- **A2.【P2】DEGRADED 状态无出边。** §6.2.1 状态转移表覆盖了 PENDING_REVIEW 回灌、MULTI_LINE_SKIPPED 恢复，但 DEGRADED 只有入边（"服务降级→DEGRADED"），服务恢复后如何迁移（回原状态？重入管线？）仅在 §3.7 以"从断点续跑"一句带过，状态机未闭合。
- **A3.【P2】复核回灌后的迭代计数与轮次上限未定义。** 回灌边（仅 mask→S8 重组装、artifact_id→S3 复跑）复用原 thread_id 还是新开？iteration 是否清零？若复核修正后 S9 再报缺陷，是否重享 3 轮上限？人工回灌理论上可与 S9 循环交替形成"人机乒乓"，建议设回灌轮次上限（如 ≤2 次，超限 FAILED）。
- **A4.【P3】附录 B mermaid 缺 S8→S10 的 PENDING_REVIEW 边。** §3.4.3 明确 route_assemble 三分流（PENDING_REVIEW→s10_review），但附录 B 图中 S8 仅画"多器物线图→S9 / 单器物→S10"两条边，复核支路缺失。

## 二、数据契约与边界假设

**通过项：**
1. 上游输入契约显式声明（§1.4），违约不做本地回退/角色补全，E102 隔离排除——"契约校验局部隔离"原则成立。
2. 降级矩阵完整（三链→双链→单链→排除，置信封顶明确），弱链① ×0.8 封顶 + degraded 标记 + provenance 溯源，"禁猜测"贯穿。
3. 失败模式覆盖较好：E100–E1100 错误码字典 + 7 类硬约束报警 + 服务级降级（VLM/SAM/OCR 不可用各有处置），无"模型 100% 准确"的理想化假设。

**问题：**
- **B1.【P1】E102 的作用域口径含混：figure 级还是报告级？** §2.1 写"摄入期校验失败 → **违约报告**转上游契约违约清单 + E102 排除"；§4.1 写"契约违约记 violations 带 fileref 与原因，figure 保留由 S1 按 E102 排除"；§6.4 写"**报告**转上游契约违约清单"。V0.4 评审实测 caption 缺失 figure 达 **6,636（43%）**——若按"报告级"排除，一本有 caption 缺失的书会被整体熔断；若按 figure 级，则与"报告转清单"表述矛盾。须统一为 figure 级隔离（与 §4.1 一致），并给出过渡期（上游契约未达成前）的 E102 排除率上报口径，作为上游质量 KPI。
- **B2.【P2】43% caption 缺失的过渡期策略依赖上游承诺，方案侧无量化预案。** 方案将 figure-title 完整性完全转移给上游（合理），但 P0 实际可用数据量 = 契约达标 figure 数，当前 examples 中间态下 P0 试跑规模会大幅缩水。建议在 §9.3 补充"E102 排除率 × 试点报告清单"的可用流量测算，避免 P0 排期失真。
- **B3.【P3】PairState 缺 alarms 字段。** 状态转移表依赖"任一硬约束报警（E001–E007）立即转 PENDING_REVIEW"，但 §3.4.2 PairState 字段清单无 `alarms`（代码 GraphState 已有）。契约定义应补齐。
- **B4.【P3】candidate_images / image_merge_mode 为"保留定义但不执行"的死字段。** 既然当前版本明确不做跨图聚合，建议从 Schema 中移除或降级为注释性附录，避免下游误以为可用（DDL 中仍有该列）。

## 三、模型与算法可靠性

**通过项：**
1. 确定性/概率边界清晰：S2 纯确定性（像素统计+XML 器物号+拓图词，无 VLM），S3/S5/S7/S8 规则驱动，仅 S6（SAM）与 S9（VLM）为概率模型——关键分流不依赖概率判断，是本方案最重要的可靠性设计。
2. S9 假阴性/假阳性均有兜底：误诊→迭代上限 3；R3 模型升级→golden set CI 门禁 + 幂等键回放。
3. 多源冲突仲裁有机制：S5 双源三链一致性仲裁 + 降级矩阵置信封顶，链①为唯一权威源。

**问题：**
- **C1.【P1】S2 五分类准确率无指标、无门禁、无观测。** S2 是 100% 流量的路由入口，且分类错误**不可逆**：single_line 误判 multi_line → 当前试点下直接 `multi_line_skipped` 归档丢数据（恢复 multi_line 后则误入 S3–S6 全链）；multi_line 误判 single_line → **整图错误 Pair 且不经 S9 终检直接输出**。但 §10.1 指标表只有 IoU/序号匹配/artifact_id 命名等下游指标，**没有 image_type 五分类准确率/混淆矩阵指标**；golden set 分层（§10.2）也没有把"S2 分类正确性"作为独立验收断言。像素判定阈值（pct20≥5、mean_chroma≥8、L∈(64,192)、mid≥15）均为经验常数且 verify 脚本"不入库"。建议：① §10.1 增补"五分类准确率 ≥ X%（P0 实测定基线）"与按类别召回（尤其 single_line→multi_line 方向）；② verify_s2_color_classifier.py 的判定口径纳入 CI golden set 回归。
- **C2.【P2】置信度数值（0.95/0.85/0.70/…）为设计约定，未经校准。** 建议在 P2 基准数据阶段用 golden set 实测校准各链组合的经验准确率，回填降级矩阵，否则阈值失去区分意义。
- **C3.【P3】S9 第 3 轮"切换更高能力档位模型"的升级路径未计入资源预算（§9.2 按档位 B 单一口径估算）。**

## 四、性能、存储与资源估算

**通过项：**
1. 存储生命周期定义完备（§9.4 五层分层 + 复核通过+7 天清理 + E1100 惰性联动），无中间态无限累积风险。

**问题：**
- **D1.【P2】资源估算仍是 V0.4 的"最坏 12 次调用"口径，未按 V0.5 拓扑重算（V0.4 评审 F1 遗留未闭环）。** V0.5 后单器物路径（约占大头）**零模型调用**（S2 确定性 + S7/S8 规则 + 不经 S9），仅 multi_line 路径消耗 VLM/SAM/OCR。§9.2 沿用 16,124×12=193,488 最坏值，GPU/时长预算失真。建议给两版口径：① 试点期（multi_line skipped，全量近零 GPU）；② 恢复后按五分类实际分布加权的期望调用数区间。

## 五、测试策略与质量门禁

**通过项：**
1. 测试分层完整：单元（确定性节点 ≥80%）/ 契约（网关录制回放 Mock）/ 集成回归（golden set CI 门禁），且补齐 StateGraph 单测、checkpointer 恢复测试、条件边路由枚举测试——比 V0.4 显著加强。
2. golden set 分层覆盖典型/边缘（无图注降级、密集基准线、纵向、同号/区间拆、彩图、排除类），标注计划含双人复核与工时估算。
3. 回归门禁量化（指标下降 >5% 阻断），prompt/阈值变更均过门禁；148 passed/3 skipped 的 skip 原因如实披露。
4. 灰度（新书 ≤5% 图）与回滚（幂等键回放 + git tag 三一致）策略明确。

**问题：**
- **E1.【P2】multi_line skipped 期间，golden set 中多器物类样本（约 68/108 图）的 CI 门禁实际不可执行。** 规则 A/同号拆/区间拆/密集基准线/纵向排版等类别当前无运行路径，"门禁全绿"会给出虚假信心。建议：① 文档明示门禁分阶段启用矩阵（试点期门禁范围=单器物/彩图/排除类）；② multi_line 恢复时把该矩阵翻转设为发布前置条件。
- **E2.【P2】golden set 缺"零 XML 信号"与"图题 ≥2 器物号"专项分层（V0.4 评审 B1/B2 遗留）。** 实测图题 ≥2 器物号仅 55 张、链①②③全缺失图占 28%，属低频高危形态；弱链①（恰 1 号降级）已入 §2.2.5 但 golden set 分层表中无对应样本层，建议补 8–12 张。
- **E3.【P3】回归门禁无人工豁免机制（谁有权豁免、豁免记录、豁免有效期）。**

## 六、人工复核与闭环反馈

**通过项：**
1. 触发条件枚举完备（E001–E007、迭代上限、连续无改善、低置信段、E005、E102 排除清单），均为确定性触发，无"过度敏感"的模糊地带。
2. 复核反哺闭环明确：复核通过样本入 golden set、季度重评、>5% 下降触发调优；增量复核避免全管线重跑。
3. 复核成本有局部估算（golden set 标注 50 工时）。

**问题：**
- **F1.【P1】§6.2.1 与 §8.2 的"仅修正 mask"回灌路径不一致。** 状态表：`PENDING_REVIEW →（复核回灌，仅 mask）→ SEGMENTED，s8 重组装，再 s9 终检 → S10`；§8.2：`仅修正 mask → 状态转 ASM_VALIDATED，触发 S8 最终输出`（**不再经 S9**）。人工修正后的 mask 是否需要 S9 复检，两处口径相反，直接影响回灌实现与复核吞吐。
- **F2.【P1】E005 边界仍与链②反推能力冲突（V0.4 评审 D1 遗留，multi_line 恢复前必须定）。** §4.5.1 seq_missing 含"图注无序号列表（含图注缺失）"即触发 E005；但链②明确具备"图引用反推 seq_id"能力（§4.3/§4.7.2）。无图注率 48.8% 的现实中，no-note 多器物图若正文有"（图三四，3）"式引用本可自动绑定，按当前口径却全量送人工。建议：链②反推成功 → 不触发 E005（按双链组合降级输出）；seq_missing 收窄为"链①缺失 ∧ 链②无反推证据"。multi_line 当前 skipped 使该问题被暂时掩盖，**恢复 multi_line 前不解决会造成 PENDING_REVIEW 海啸**。
- **F3.【P2】全量复核的人力吞吐预算缺失。** 有 golden set 标注工时，但无"预计 PENDING_REVIEW 图数 × 单图复核时长"的稳态人力测算；§9.3 的批次暂停阈值是事后兜底，建议补复核消化速率预算与积压报警线。
