1. 项目概述与目标
1.1 任务定义
本方案针对考古报告结构化文件（DocBook XML）与线图图像，设计一套 Supervisor-Worker 多智能体图文配对数据构造管线，实现"大图拆小图、图文配对、异常闭环"三大核心能力，产出服务考古大模型训练与评测的高质量语料。
交付对象为（器物号, 图像, 描述文本）三元组：
图像：经过掩膜分割后的单件器物线图子图（含该器物所有视图、说明文字、专属比例尺），或单张彩板照片；
描述文本：正文中按 artifact_id 切分的该器物专属描述段；
artifact_id：跨图、跨章节的唯一关联键，全文统一为 book_id:artifact_id 形式。
1.2 数据特征描述
本节描述的数据特征基于 21 份考古报告 XML 实测抽象（examples 全量、非抽样），仅作为样本反映考古报告领域的典型形态分布；方案必须能泛化到未纳入样本的报告。实测规模：16,124 个 imagedata、media 约 2.4GB（压缩 jpg，平均约 143KB/张）。
量化口径与来源（E3）：全文量化数字以 21 份报告 XML 实测为准（图数 16,124 imagedata、media≈2.4GB、单图≈143KB），来源为本文 §3.2 数据规模验证与 V0.3 评审报告附录 A 实测统计；如与早期版本估算冲突，以实测为准。
1.2.1 图像像素特征
实测中存在的像素形态，必须前置声明：
[TABLE]
| 形态 | 图题位置 | 代表样本 | 本项目状态 |
| 书内 media | 在 XML 中，不在像素 | 万州余家河墓群 media/image1.jpg | 本项目实际交付形态 |
[/TABLE]
像素三要素：器物线图（占主体）、图片内序号（1.、2.、3等，可能缺失）、比例尺（带刻度图形 + 文字）。
1.2.2 XML 结构化特征
图题（caption role="figure-title"）：如 "图二六 地层出土帽钉"，含图号与描述性文字。
图注（para role="figure-note"）：如 "1. 骨笄"，"1～4.豆（M3：4、M3：2、M3：3、M3：1） 5.壶（M3：5）"，声明 seq→artifact_id 映射。
正文（para）：含每件器物的描述（质地、尺寸、纹饰、复原状态）及图引用 "（图一〇，2）"，可反推 artifact_id→描述。
1.2.3 非器物图与彩板特征
非器物图：平面图、剖面图、区位图、墓室图、遗迹图、发掘场景照等。典型样本：图二-1-3 M4墓室平面图。
彩板：图版一/圖版N 形式的彩色照片（赵廷隐墓图版一为墓葬中部十字隔梁场景照）。本项目按 P0 范围纳入。
彩板形态特征：单张彩色照片 + 条目号（如 1, 2, 3，可能缺失）+ 图版标题；条目与器物号映射在正文 "（图版N，1）" 处声明。
彩板二分：plate_artifact（器物彩板，单张/多张器物彩色照片，进入 S7 构造 Pair）与 plate_scene（场景照彩板，如墓葬隔梁/夯土/发掘场景，归 discarded 仅存档）。S2 必须区分二者，不得仅凭"图版/圖版"关键词判 plate。
1.3 核心挑战
本方案将核心挑战收敛为三个，每个挑战对应独立的工程目标与验收指标。
[TABLE]
| # | 挑战名称 | 工程目标 | 验收指标 |
| C1 | 切图：多器物线图掩膜分割 | 单图多器物像素级分离，禁 bbox、禁像素补全 | mask IoU ≥ 0.85；硬约束零违规 |
| C2 | 组图：多视图归组与同号拆 / 区间拆 | 规则 B 合并、规则 A 拆分、同号拆 Pair、区间拆 Pair 全部正确 | 归组 F1 ≥ 0.95；同号/区间拆分 100% 正确 |
| C3 | 闭环：Supervisor-Worker Loop Engineering | 诊断缺陷类型驱动针对性二次修正，不依赖盲目重试 | 单图无改善提前转 PENDING_REVIEW 准确率 ≥ 80% |
[/TABLE]
3个挑战与三大能力（切图/组图/闭环）一一对应。
1.4 任务边界
确认以下任务边界：
能力接口不冻结选型：VLM/SAM/OCR/编排框架均以能力契约描述，不指定具体型号，P0 POC 后冻结。
无器物号报告排除存档：见 §2.5。
器物号命名空间隔离：以 book_id 为前缀隔离各报告 artifact_id，不跨报告合并。
双源三链泛化降级：链①图注 / 链②正文 / 链③图内 OCR，缺链时自动降级（三链→双链→单链→排除）。
解析规范硬约束不可关：掩膜分割 / 序号硬匹配 / 比例尺三级 / 报警即人工 / 禁猜测 / 禁自动回退，不可被 flag 关闭。
上游输入契约：上游结构化工作保证 figure-title 角色完整、figure-note 角色正确（可整图级缺失）、media 像素为线图+序号+比例尺；本系统在摄入期做契约校验，违约报告转"上游契约违约"清单并排除，不做角色补全/结构回退（评审 N1 的 B 计划）。
Feature Flag 可选逻辑可开关：S3 LLM 二次确认 / S9 闭环 / 跨图合并 / 纵横向旋转校正可独立开关以便 A/B 对比；硬约束（掩膜/硬匹配/比例尺三级/报警即人工/禁猜测/禁回退）不可关。
1.5 策略基线
策略基线（链①规则归组 + 序号硬匹配 + SAM 分割），调用 Supervisor VLM 诊断分割效果，如失败Supervisor VLM指导SAM进行迭代分割。

2. XML结构与适配策略
以"上游输入契约"为前提：上游结构化工作交付的 XML 与图像满足单一标准型契约（caption role="figure-title" + para role="figure-note" 角色正确、media 像素为线图+序号+比例尺）。该契约由上游保证并在摄入期校验，而非本系统对异构原始数据的兼容承诺。
2.1 XML 结构
[TABLE]
| 分类 | 特征 | 代表样本 | 适配策略 |
| 标准型 | caption role="figure-title" + para role="figure-note" 完整 | 万州余家河、郑州商城 | S1 解析器直连 |
| 契约违约型 | caption 无 role / figure-title 缺失等不满足契约 | 洪洞南秦（上游处理前形态） | 摄入期校验失败 → 上游契约违约清单 + 排除，不本地回退 |
[/TABLE]
2.2 器物号体系（两步归一化）
器物号正则匹配在实测中需解决三类问题：①"2004CWWM11:5" 的长前缀匹配；②"H83①:35"、"T18④:7"、"⑤:40"圈号层位号匹配；③"M369∶4" 比例冒号匹配。本方案采用"先归一后匹配"两步法。
2.2.1 步骤一：归一化
冒号统一：U+2236（∶）、U+FF1A（：）、U+003A（:）全部归一为 ":"。
圈号归一：①–⑳ 归一为 1–20，作为前缀字符或数字序号的一部分保留。
全角字符半角化：括号、引号、字母。
大小写统一：前缀大写。
2.2.2 步骤二：匹配正则（前缀字符集扩展）
典型形如：M4:6、00FBG1:2、2004CWWM11:5、H83:35、T18:7、⑤:40、M369:4（∶已归一）；并扩展覆盖 C5.1H146:1（长前缀含点号）、Bb9/Zhb2（字母+数字部件号）。前缀字符集在归一化后允许字母、数字、点、连字符组合。
2.2.3 命名空间隔离
Pair 逻辑键统一为 book_id:artifact_id，全局唯一；文件目录按 book_id 隔离。
2.2.4 单测反例
M369∶4（后屯墓地，比例冒号）→ 匹配 M369:4
2004CWWM11:5（万州瓦子坪）→ 匹配 2004CWWM11:5（前缀不被截断）
H83①:35（栎阳城）→ 匹配 H83①:35（圈号作为前缀字符）
T18④:7（栎阳城）→ 匹配 T18④:7
⑤:40（栎阳城单圈号）→ 匹配 ⑤:40
C5.1H146:1（郑州商城，长前缀含点号）→ 前缀 C5.1H146 完整保留
Bb9 / Zhb2（唐懿德太子墓，部件号）→ 字母+数字整体作为 artifact_id
Zhb2 / Zhb7（唐懿德太子墓，倚柱号）→ 字母+数字整体作为 artifact_id
406号墓（长沙青振，自然语言墓号）→ 语义级识别为出土单位编号，不进入 M/T/H 正则
2.3 图号编号体系
中文数字：图一、图二、图一〇、图二六
章序式：图 2-1-16、图 2-1-4（用 - 而非 .）
点号式：图5.85、图2.3.1
繁体：圖二、圖九
图版/拓片：图版一、图版二、拓片三七
图号提取规则：图号+可选后缀（图二六a、图2-1-16b），后缀完整保留。
2.4 XML 适配层设计
适配层由主链解析器组成。上游结构化工作已保证 figure-title 和 figure-note 的正确解析，本系统无需进行角色补全。
主链解析器：遍历文档序将 figure 与其后紧邻的 figure-note para 关联，提取 imagedata fileref、caption、note_text 等字段。
2.5 无器物号报告处理
对于不使用器物号体系的报告，无法构造 Pair，需前置检测并排除。检测采用多信号综合判定（不仅靠正则密度）：① figure-note 器物号密度；② 正文图引用（图X，N）密度；③ 器物描述段（质地/尺寸/纹饰）存在性。三者皆无才判定无器物号；对 Bb9/406号墓 等非 M/T/H 形态先做 §2.2 扩展匹配，避免误排除有效报告。

3. 总体架构设计
本方案采用"调度员 + 专职 Worker + Supervisor VLM"的多智能体协作架构。调度员是唯一的全局状态持有者，其他智能体均为无状态的 Worker，Supervisor VLM 作为全局质量中枢对各 Worker 产出进行结构化诊断并驱动针对性二次修正。架构图见下。

图3-1  考古报告图文Pair数据构造 · Supervisor-Worker 多智能体总体架构
3.1 多智能体协作架构
数据流从 DocBook XML 与 media images 输入开始，依次经过 S1 解析 -> S2 图类判定 -> 三路并行（线图主管线 / 彩板简化线 / 非器物图存档）-> 双源三链对齐 -> 掩膜分割 -> 匹配组装 -> Supervisor 诊断与回环 -> 输出 / PENDING_REVIEW 队列。
调度员根据 Supervisor 诊断报告动态决定下一步跳转目标：可能跳回 S6 重新分割（case_mask_incomplete），可能跳回 S3 重新切分正文（case_text_split_err），可能跳回 S5 重新对齐（case_ocr_miss）。这种"诊断驱动路由"是 Loop Engineering 的核心。
3.2 各智能体功能概览
[TABLE]
| 编号 | 名称 | 职责一句话 | 上下游 |
| S1 | 报告索引器 | 解析 DocBook XML，直接消费上游 figure-title/figure-note 解析结果，关联 figure 与 figure-note，检测无器物号报告 | — → S2 |
| S2 | 图类判定器 | 按 XML 图题关键词与视觉内容判定 image_type（line_drawing / plate / discarded），地层特例强制 type A | S1 → S3+S4 / S7 / 存档 |
| S3 | 文本源解析器 | 解析 XML 图注文本（语法解析器）与正文（切分决策树），输出 seq→artifact_id 映射与描述文本 | S2 → S5 |
| S4 | 图像源解析器 | OCR 像素中的序号、比例尺文字与说明文字，支持横纵排版、组列标签；不 OCR 图题与图注 | S2 → S5 |
| S5 | 融合仲裁器 | 双源三链对齐，产出 fused_mapping 与 case_type | S3+S4 → S6 / S8 |
| S6 | 视觉分割器 | SAM 实例分割线图与彩板，输出 mask 三件套（线图+说明文字+专属比例尺） | S5 → S8 |
| S7 | 彩板解析器 | 从 XML 图题提取图版标题，条目号识别，条目→artifact_id 映射，输出单张彩图与条目 | S2 → S8 |
| S8 | 匹配组装器 | 规则 A 拆分 / 规则 B 合并 / 同号拆 / 区间拆 / 跨图合并，输出 PairRecord | S5/S6/S7 → S10 |
| S9 | Supervisor VLM | 对 Worker 产出结构化诊断，产出 DiagnosticReport 驱动针对性二次修正 | 任意 → 任意 |
| S10 | 调度复核桥接器 | PENDING_REVIEW 与 Label Studio 双向同步，幂等回写，事件驱动 | S9 → LS / PENDING_REVIEW |
[/TABLE]
3.3 Supervisor-Worker 范式（核心）
本方案统一采用 Supervisor-Worker 范式术语。Supervisor-Worker 是行业中立的术语接口，利于跨团队协作。
本范式与"失败即重试"的本质区别：传统重试无指导信息，盲目重跑整个管线；Supervisor-Worker 是诊断缺陷类型后针对性修正，指导信号明确告诉 Worker 哪里出了问题、怎么修。
以视觉分割为例，闭环如下：
S6 视觉分割器初始分割 → 候选 mask[]
S9 Supervisor 诊断：structure = {under_seg, over_seg, mask_incomplete, scale_mismatch, ...}
S9 产出 DiagnosticReport：target_agent=S6, correction_action=add_positive_prompt@coordinates, action_params={point:(x,y), threshold:0.88}, expected_result=mask_count==5
S6 按指导信号执行针对性二次分割
S9 再诊断：缺陷数递减 → 继续；连续两轮无改善 → 判定不收敛 → PENDING_REVIEW；达 3 次迭代上限 → PENDING_REVIEW 且携带完整诊断报告
此范式可泛化到所有智能体对：S3 文本切分错误时 Supervisor 给出边界修正建议；S4 OCR 漏读时 Supervisor 给出区域重读坐标；S5 仲裁冲突时 Supervisor 给出"哪源更可信 + 依据"。

3.4.2 State Schema（F3）
单一全局 PairState 承载跨节点运行时状态；FigureState 是持久化聚合状态，PairState 由 FigureState 转换而来。为避免双状态漂移，所有新增字段必须先落到 FigureState，再通过 to_pair_state()/from_pair_state() 同步；子模型字段级定义见 §6.1。
class PairState(BaseModel):  # LangGraph 全局 State（跨节点共享）
    book_id: str; figure_id: str; fileref: str
    caption: Optional[str]; figure_note: Optional[str]      # S1 写入（XML）
    image_type: Optional[ImageType]                          # S2
    note_items: list[NoteItem]                               # S3 链①
    text_artifacts: list[TextArtifact]                       # S3 链②
    seq_annotations: list[SeqAnnotation]                     # S4 链③
    scale_annotations: list[ScaleAnnotation]                 # S4 链③
    fused: Optional[FusedMapping]                            # S5
    masks: list[MaskRecord]                                  # S6
    assembled: bool = False                                  # S8 是否已组装
    pair_records: list[PairRecord]                           # S8 / S7
    diagnostic: Optional[DiagnosticReport]                   # S9
    iteration: int = 0; defect_history: list[int] = []       # S9 收敛判定
    status: FigureStatus = 'INIT'; exclude_reason: Optional[str]
    trace_id: str; flags: PipelineFlags                      # 生命周期/开关
节点局部变量（不进 State）：SAM 原始候选 mask、OCR 原始区域、提示点中间量、旋转矩阵——仅在节点函数内使用，结果写回 State，避免 State 膨胀与序列化成本。
3.4.3 条件边 / 路由表（F4）
s9_supervise 之后用 add_conditional_edges，route_on(state) 按下表路由；guard 为 iteration<3 且 cost<cap：
[TABLE]
| guard（条件） | 目标 Node | 说明 |
| defect_list 空 且 未 assembled | s8_assemble | 分割收敛 → 组装 |
| defect_list 空 且 assembled | s10_review | 组装收敛 → 复核/输出 |

| 含 group_error 且 iteration<3 | s8_assemble | 按证据重归组 |
| iteration>=3 或 连续两轮无改善 或 成本帽 | s10_review | 转 PENDING_REVIEW |
[/TABLE]
3.4.4 checkpointer 与断点续跑（F5）
thread_id（checkpointer） = book_id:figure_id:rule_version:prompt_version:judge_prompt_version，不含 iteration；轮次级调用幂等键 = thread_id:iteration。P0 用 SqliteSaver（零依赖、单文件、易调试）；生产切 PostgresSaver 复用现有 PG（切换点为创建 checkpointer 的工厂函数）。与 §5.8 幂等、§9.3 任务认领分工：claim（PG SELECT FOR UPDATE SKIP LOCKED）决定“哪个 Worker 跑该 figure”，checkpointer 决定“中断后从最近 State 续跑”。
3.4.5 interrupt/resume 与人工复核（F7）
s10_review 进入 PENDING_REVIEW 时调用 interrupt() 暂停子图并落 checkpoint；S10 创建 LS 复核任务。LS webhook 回灌后以 Command(resume=review_result) 恢复，event_id 幂等去重；仅修正 mask 直接 OUTPUT，修正 artifact_id/seq 则回跳 s3 增量重跑。
3.4.6 编排拓扑（F6）
拓扑含三条关键边：S6→S9→S6 分割回环、S9→S8 归组、S10→PENDING_REVIEW。可编辑拓扑图见图3-2；mermaid 源码见附录 B，随代码维护。

3.5 状态机与数据流
每个被处理的 Figure 在整个生命周期内维护一个 FigureState 状态对象。状态包含：INIT -> PARSED -> CLASSIFIED -> ALIGNED -> SEG_DIAGNOSED -> SEGMENTED -> ASM_VALIDATED -> OUTPUT 主路径；支路 CLASSIFIED_PLATE -> ASM_VALIDATED -> OUTPUT；异常路径 PENDING_REVIEW / EXCLUDED / FAILED / DEGRADED。调度员根据当前状态与 Supervisor 诊断报告决定下一个跳转目标，数据流的核心特征是"每一步都可回环"。
3.6 双源三链泛化机制
[TABLE]
| 链 | 来源 | 内容 | 作用 |
| 链① | XML figure-note | seq→artifact_id 显式声明 | Pair 键的唯一权威源 |
| 链② | XML 正文 | artifact_id→描述 + 图引用反推 seq | Pair 文本侧来源 |
| 链③ | 像素 OCR | seq 位置 + 比例尺文字 | Mask 锚点 + 校验 + 比例尺归属 |

| ✗ | ✓ | ✗ | 单链②（仅正文） | 0.60 |

[/TABLE]
3.7 服务级降级与熔断
长时跑批中任一模型服务抖动即可能全停。本方案设计服务级降级策略。
VLM 不可用：S2 退化为图题关键词规则（含地层特例匹配）；S5/S9 全部转 PENDING_REVIEW。
SAM 不可用：S6 全部转 PENDING_REVIEW；当前批次挂起而非失败。
OCR 不可用：链③标记缺失；按双链或单链②降级；置信封顶 0.70。
熔断：单服务连续 3 次失败触发熔断 60 秒；5 分钟内失败率 >50% 触发全批次暂停 + 报警。
回退：服务恢复后从断点续跑（基于 FigureState 幂等键）。

4.3 S3 文本源解析器
职责：解析 S1 交付的图注与正文，输出 seq→artifact_id 映射与描述文本。图注文本来自 XML figure-note，采用语法解析器解析；图注缺失（链①不可用）时跳过本步，由 S5 按降级矩阵处置。
S3 为纯解析节点：链①图注语法解析与链②正文反推（artifact_id→描述、图引用反推 seq）均归 S3；S5 不做反推，仅做仲裁。图注解析采用 NoteParser 策略接口：§5.6 各语法用例注册为独立 parser，新增用例通过注册扩展，不改动主流程。
4.3.1 图注解析器
用例（节选）：

4.3.2 正文切分决策树
决策树目的是按 artifact_id 切分描述段。
1. 扫描正文段落，提取 artifact_id 锚点序列 A = [a1, a2, ...]
2. 若段落含多个 artifact_id，按 "标本X:1，夹砂灰陶……" 模式切分
3. 若段落单 artifact_id 且无明显边界信号，整段归属该 artifact_id
4. 若段落无 artifact_id：
   a. 检测件数语 ("1件。"、"2件。") → 归并最近上文 artifact_id
   b. 检测标本号 ("标本M140:5") → 归并对应 artifact_id
   c. 描述中夹图引用 "（图5.85、图5.86）" → 保留为 provenance
   d. 整段无信号 → 挂最近上文 artifact_id
5. 低置信度段（步骤 4c/4d 触发）送 LLM 二次确认
输出 TextArtifact Schema：
4.3.3 高 figure-note 缺失率报告链②反推专项（D4）
④ 低置信段 LLM 兜底（s3_llm_confirm 默认开启，仅允许在 golden set 回归通过后关闭）
  source_para_ids: list[str]  # 溯源
  markers: list[str]          # ['sample_id', 'piece_count', 'fig_ref']
4.4 S4 图像源解析器
职责：仅 OCR 图像像素侧内容：图片内序号、比例尺文字、线图旁说明文字；支持横纵排版与组列标签。图题与图注来自 XML，不在 OCR 范围。
4.4.1 OCR 契约
横纵排版检测：先检测图面整体方向（从比例尺区与序号区文字方向推断），传入对应 OCR 模型。
组列标签："2、3." 整体作为一个 OCR 目标，识别为 group=[2,3]。
单序号多连通域：识别 "1." + 对应多个 mask 区域（rule_b 的特征，序号 1 下含多个不连通视图）。
输出：SeqAnnotation {text, bbox, mask_ref?, group?}；ScaleAnnotation {text, bbox, unit, value, seq_ref?}。
4.5 S5 融合仲裁器
职责：双源三链对齐，输出 fused_mapping（seq→artifact_id 映射 + case_type）。
S5 为纯仲裁节点：对 S3（链①+链②）与 S4（链③）的映射做一致性仲裁与置信评估，产出 fused_mapping 与 case_type；不执行任何文本反推。
4.5.1 case_type 枚举
[TABLE]
| case_type | 含义 | 判定依据 | 下游处理 |
| rule_a | 多器物图：图注含序号列表，各 seq 对应独立线图 | 链①声明 seq 列表，与像素序号可一一对应 | S6 按 seq 拆分，S8 逐器物出 Pair |
| rule_b | 单器物多视图图：全图视图同属一个 artifact_id（含单视图退化形） | 链①/链②仅声明一个 artifact_id，或 S9 判定多视图同器 | S6 整图分割，S8 合并出图 |
| split_same_seq | 同号多器：同一 seq 对应多个 artifact_id | 图注形如 "2、9.铁器（00FBH1:6、00FBH1:3）" | 按 artifact_id 拆为独立 Pair，共享掩膜溯源 |
| range_split | 区间序号：区间 seq 对应多个 artifact_id | 图注形如 "1～4.豆（M3:4、M3:2、M3:3、M3:1）" | 按 artifact_id 拆为独立 Pair，共享掩膜溯源 |
| seq_missing | 无序号多器：图面多个器物线图但图注无序号列表（含图注缺失） | 无法建立 seq↔artifact_id 对应 | 触发 E005 报警，PENDING_REVIEW |
| plate | 彩板图 | XML 图题匹配图版/圖版样式 | 进入 S7 彩板管线 |
| discarded | 非器物图 | 视觉判定与图题关键词否决 | 仅存档，不构造 Pair |
[/TABLE]
4.6 S6 视觉分割器
职责：SAM 实例分割线图与彩板，输出 mask 三件套（线图 + 说明文字 + 专属比例尺）。
4.6.1 掩膜三件套契约
线图 mask：基于 SAM 自动分割，初始自动模式出候选 mask[]。
说明文字 mask：紧邻线图旁的 OCR 区域（如 "盖顶面纹饰"、"颈部"、"主视图"、"侧视"），必须作为 mask 不可分割部分。
专属比例尺 mask：按 §5.4 比例尺三级归属（硬匹配 > 全局共享 > 报警）。
重叠处理：仅提取自身 mask 像素，禁像素补全。
禁止项：bbox 切割、bbox 内 mask 补全、跨 mask 像素借用。
4.6.2 纵横向检测算法
检测器：
抽取比例尺区与序号区文字；
用文本方向分类器判断单向 vs 多向；
若多向 → 整图旋转 90° 进行方向统一（S9 监督）。
旋转时同步：专属比例尺 + 线图 + 说明文字采用同一旋转矩阵。
4.7 S7 彩板解析器
职责：从 XML 图题提取图版标题，条目号识别，条目→artifact_id 映射，输出单张彩图与条目。
4.7.1 图版版面识别
图版标题识别：XML figure-title 匹配 "图版[一二三四五六七八九十百千0-9]+"、"圖版[一二三四五六七八九十百千0-9]+"、"图版[-\s]?[0-9]+" 样式并提取图版号；图版标题不在像素中 OCR。
条目号识别：像素 OCR 识别 "阿拉伯数字 + . 或 、"，如 "1."、"2、"、"1、3"；条目号是彩板像素侧的主要 OCR 目标。
上游解析正确前提下，图版标题与图注以独立 XML 节点交付，S7 不做版面粘连兼容，仅校验图版号连续性与条目映射完整性。
4.7.2 条目→artifact_id 映射
从正文 "（图版N，1）" 中反推：扫正文段落，提取图版引用正则 pattern = "（图版?(\d+|[一二三四五六七八九十百千]+)，\s*(\d+)"。
建立 mapping={图版N: {条目序号: artifact_id}}。
实测图版引用存在半角括号/逗号变体（如 "(图一八七, 9; 图版一一二, 6)"），按 §2.2.1 全角半角归一化后再匹配。
形态学特例：
赵廷隐墓图版提及 1018 处，远超其他报告，需用预编译的 corpus 词表加速。
栎阳城图版标题为 "图版 N"（带空格），需正则兼容。
4.7.3 Pair 构造
"彩图都是一张"：每张彩板图保留单张图（不做分割），通过条目号→artifact_id 映射与正文描述关联，构成 Pair。
彩板路径与线图路径共享 S8 匹配组装器与 S9 Supervisor 质检。
4.8 S8 匹配组装器
职责：按 fused_mapping 拆分/合并 mask，输出 PairRecord 与跨图合并决策。
4.8.1 多视图归组决策
多视图归组决策遵循 "显式声明优先、判定次之、不猜测" 原则：
链①或链②显式声明同一 artifact_id 下多个 seq/视图 → 直接判定 rule_b，S8 合并。
无显式声明，图面无序号列表且多视图共享基准线/对齐关系 → S9 Supervisor 按 §5.7 三重证据判定，判定证据记入 DiagnosticReport。
判定证据不足或两链冲突 → 不合并，触发报警转 PENDING_REVIEW。
归组结果仅处理 "同图内多视图合并"；跨图同器物合并见 §4.8.2。
归组判定与执行收敛于 S8：S8 一次性向 S9 请求归组证据并据此执行合并；证据不足直接转 PENDING_REVIEW，不做 S8/S9 多轮往返。跨图合并（line_drawing+plate 同 PairRecord）受 Feature Flag cross_fig_merge 控制，P0 默认关闭；关闭时仍保留同一 artifact_id 的全部候选图，按 §4.8.2 选主图并写入 candidate_images，不因唯一键冲突丢图。
4.8.2 跨图合并规则
交付定义为"一个 artifact_id 一个 Pair"。实测发现同 artifact_id 跨图出现（如线图主图 + 彩板图版）。合并规则：
逻辑键：book_id:artifact_id 全局唯一。
合并维度：line_drawing（mask 子图）+ plate（单张彩图）合并为同一 PairRecord；未开启 cross_fig_merge 时，线图优先为主图，plate 存为候选图。
冲突处理：同图版条目多 artifact_id 走同号拆 Pair。
图版缺失：仅线图也算完整 Pair；不强制要求彩板存在。
多候选保留：同一 artifact_id 在不同图/图版出现时，选择主图写入 image_path，其余候选写入 candidate_images，记录 source_figure_id、role、confidence；不删除候选。
4.9 S9 Supervisor VLM
职责：对 Worker 产出结构化诊断，产出 DiagnosticReport，驱动针对性二次修正。S9 分为必选终检与可选迭代：每个进入 S9 的 figure 至少执行 1 次终检；当 s9_loop 开启时，按 §4.9.2 进入最多 3 轮修正回环。

5.2 Supervisor-Worker Loop Engineering
DiagnosticReport 是 S9 驱动针对性修正的结构化指导信号，字段定义如下：
[TABLE]
| 字段 | 含义 |
| trace_id / report_id | 诊断轮次唯一标识，关联 FigureState 与模型调用录制 |
| figure_id | 诊断对象图标识 |
| defect_list | 缺陷项列表：缺陷类型（§4.9.1）、位置描述、严重度 |
| target_agent | 修正目标智能体（S3/S4/S6/S8） |
| correction_action | 修正动作名称：加正向提示点、区域重读、边界修正等 |
| action_params | 修正动作参数：坐标、阈值、区域范围等 |
| expected_result | 修正结果验收条件：如 mask 数量达到预期值 |
| iteration | 当前迭代轮次（上限 3，见 §4.9.2） |
[/TABLE]
闭环流程：S9 产出 DiagnosticReport → 调度员按报告路由至目标智能体 → Worker 执行针对性修正 → S9 复诊 → 缺陷数递减直至收敛；连续无改善或达迭代上限转 PENDING_REVIEW（见 §3.3、§4.9.2）。本节仅给逻辑级字段定义，S6–S9 回环的 IR 样例在 P0 POC 后另行交付。
5.3 序号硬匹配与比例尺三级
序号硬匹配规则（附录 A 解析规范强制）：
序号文本三来源：XML 图注序号（链①，S1 交付）、像素线图旁序号（链③，OCR）、像素比例尺旁序号（链③，OCR）。
仅以 OCR 文本完全一致作为匹配标准（如 "1." ↔ "1" ↔ "1."）。
严禁坐标距离、空间位置推断。
比例尺三级归属：
[TABLE]
| 级别 | 条件 | 动作 | 是否报警 |
| 一级 | 比例尺旁有明确序号文本 | 按该序号硬性绑定 | 否 |
| 二级 | 全图仅 1 个比例尺（无论是否标序号） | 视为全局共享，复制给所有无专属比例尺的线图 | 否 |
| 三级 | ≥2 个比例尺且至少 1 个无序号 | 无法硬匹配 | 是（PENDING_REVIEW） |
[/TABLE]
组列标签 "2、3."：整体作为一个 OCR 目标，识别为 group=[2,3]；该比例尺复制给 2 与 3 两个线图。
单序号多连通域：序号 "1." + 对应多个 mask 区域，识别为 group_view=[seq=1, masks=[mask_a, mask_b]]；由 S9 按多视图归组诊断（§4.9.1 group_error）。
5.4 SAM 掩膜分割策略
初始分割：自动模式对整图提取候选 mask[]。
提示点策略：S9 指导信号 → 增/减正/负提示点 → 二次分割。
共享比例尺复制：全图仅 1 个比例尺 → 生成每个子图时复制一份。
纵横向检测：先检测画布方向 → 多向时整图旋转 90°（S9 监督）；同步旋转线图 + 说明文字 + 比例尺。
轮廓闭合校验：mask 轮廓闭合 → pass；不闭合 → 触发 mask_incomplete。
重叠处理：自身 mask 像素集，禁补全。
说明文字与比例尺并入掩膜的算法：OCR 文本区域先转 mask，再与所属线图 mask 做像素级 union，最后与专属比例尺 mask union；跨器物文字或比例尺先按 seq 归属，再合并，禁止借用非自身区域。SAM 对密集线图或共享基准线失败时，降级使用轮廓闭合+连通域候选；仍无法满足闭合约束则触发 mask_incomplete。
5.5 正文切分算法
目标：按 artifact_id 从正文切分描述段，输出 TextArtifact 结构，作为 Pair 的文本侧输入。处理步骤：
锚点抽取：扫描正文段落，按 §2.2 归一化匹配正则抽取 artifact_id 锚点序列。
单锚点段：整段归属该 artifact_id。
多锚点段：按 "标本X:1，……" 边界模式切分，各段归属对应锚点。
整段无信号则挂最近上文锚点并标记 no_anchor，进入强制 LLM 确认。
低置信段（无锚点归并）必须送 LLM 二次确认，确认依据写入 markers；s3_llm_confirm 默认开启，关闭前须通过 golden set 回归门禁。
输出字段：artifact_id、描述文本、source_para_ids（来源段落溯源）、markers（归并依据：标本号/件数语/图引用/无锚点）、figure_refs（图引用）、confidence。
5.6 图注语法用例
图注解析器以附录 A 一篇 3 的两类编号区分为前提，覆盖以下实测语法用例（含噪声与退化形态），解析输出 seq→artifact_id 映射与条目名称：
单号单铭："1.骨笄"
单号多铭："1. 陶豆 2. 陶壶"
编号+括号："1. 骨笄（M4:1）"
组列+括号："1、2. 陶豆（M4:2、M4:1） 3. 铜剑（M4:3）"
区间+同号："1～4.豆（M3：4、M3：2、M3：3、M3：1） 5.壶（M3：5）"
同号式："2、9.铁器（00FBH1:6、00FBH1:3）"
字母序号："A. 盗坑（长沙青振）"
公式残迹："$1\sim 4$ 陶豆 5.陶壶"
纯比例尺噪声："0 8厘米" → 识别为非器物条目，跳过
无空格："1.00FBG1:2"（白帝城）→ 序号与 artifact_id 紧贴
组列标签："2、3. 0 8厘米"（1.png 比例尺）→ 识别为 group=[2,3]+scale
占位缺号："3～7. 陶豆"（无 artifact_id）→ name_inferred 类别
图版专用："拓片三七 石椁内西壁（Bb9）线刻"（唐懿德太子墓）→ 图版路径，不进入 S3 主管线
无锚点："1. 陶罐 2. 陶钵" → name_inferred，走 Supervisor 归组
粘连："三塊板的長、厚和 C1同。在这一層的 12 塊蓋板的上面……"（长沙青振，描述段落）→ 描述段而非图注
余项语境："另见第三批同出器物（M4:5）"（正文引用）→ 转化为 seq 1 artifact_id 引用
地层描述："第3层：唐代文化层。厚 $0.03\sim 0.3$ 米。出土唐代板瓦……"（唐懿德太子墓）→ 描述段，非图注
完整圆圈："①" → 数字 1（圈号归一）
前缀带 -："M4-1:2" → M4-1:2 解析（注意 M4-1 是完整前缀，不是 M4 与 1 拆分）
上下文 artifact_id："（Bb9）" 而非 M/T/H 前缀 → 按链②正文证据归组；证据不足转 PENDING_REVIEW
5.7 多视图归组策略
三级 VLM 判断仍是归组难点的主战场。Supervisor 基于三重证据：
视觉证据：线图器形是否一致、是否共享基准线或对齐线、空间是否邻近。
文本证据：图注中的视图名（如 "盖顶面纹饰"+"颈部" → 同器物不同部位；"主视图"+"侧视" → 同器物不同角度）。
映射证据：链①/链②是否声明同 artifact_id 多个 seq。
归组后合并为单图：保留所有视图 + 全部说明文字 + 所有专属比例尺；整体旋转至横向；保持原始相对坐标与方位。
同号拆 Pair："2、9.铁器（00FBH1:6、00FBH1:3）" → 两个独立 Pair，共享同一 mask 路径但 artifact_id 不同。
区间拆分："2~5. 圭（M6:5-1、M6:4-1、M6:4-2、M6:5-2）" → 4 个独立 Pair，共享 mask 路径。
5.8 幂等与可复现
幂等键分两层：checkpointer 线程键 = book_id:figure_id:rule_version:prompt_version:judge_prompt_version；单轮调用/产物键 = 线程键:iteration。
原子写：tmp + rename 原子语义。
录制回放：网关层录制每次模型调用 + 响应（详见 §9.1 部署拓扑）。
Claim 机制：任务队列用 SELECT FOR UPDATE SKIP LOCKED 或队列原子的认领机制。
Webhook 幂等：event_id 唯一去重。
断点续跑：每节点落 checkpoint，进程重启从最近未完成节点继续。

5.9.2 批时长估算
以 21 份示例 XML 实测 16,124 imagedata、media 约 2.4GB 为基准

5.9.3 单图成本帽
单图成本上限 CNY 2.0；耗尽后自动 escalate PENDING_REVIEW。

6.2 状态机
每张图在生命周期内维护一个 FigureState。主路径：INIT → PARSED → CLASSIFIED → ALIGNED → SEG_DIAGNOSED → SEGMENTED → ASM_VALIDATED → OUTPUT；彩板支路：CLASSIFIED_PLATE → ASM_VALIDATED → OUTPUT；异常状态：PENDING_REVIEW、EXCLUDED、FAILED、DEGRADED。状态转移规则：
前向转移由 Worker 完成事件驱动；回跳仅由 S9 诊断驱动（case_* 路由，见 §3.1），不存在无条件重试回跳。
任一硬约束报警（E001–E007）立即转 PENDING_REVIEW，禁止输出任何 PNG（§7.4）。
PARSED 阶段判定无器物号的报告转 EXCLUDED，不进入主管线（§2.5）。
服务级降级（§3.7）转 DEGRADED，记录降级链组合与置信封顶。
全部状态转移落库并携带 trace_id，支持断点续跑与审计（§5.8、§9.3）。

6.5 数据库 Schema 与索引设计
核心四表（PostgreSQL，DDL 经 Flyway/Liquibase 迁移管理，V001__init.sql 起）：figure_states（单图生命周期）、diagnostic_reports（诊断历史 JSONB）、pair_records（Pair 产出）、review_tasks（LS 复核任务）。关键约束与索引：

diagnostic_reports：figure_id 外键 + (figure_id, iteration) 索引；JSONB 列用 jsonb_path_ops GIN 支持 @> 查询。

中间 mask 清理为定时任务（每日）+ E1100 磁盘满时惰性联动清理（O10）。

7.1 Pair 逻辑键 vs 文件物理名
[TABLE]

7.2 文件命名规范
严格遵循附录 A 解析规范第二篇 5 条：
格式：原图名称_图片内序号_器物号.png
冒号归一：artifact_id 中所有冒号（:、：、∶）→ 连字符（M4:6 → M4-6）
重名防冲突：同名图号自动追加 _N 序号（从 _1 开始），如 图七_1_M2-1.png、图七_2_M3-1.png
后缀保留：图号含字母或数字子编号（图七a、图2-1-16b）必须完整保留
原图名取值：从 XML figure-title 中按 §2.3 图号规则提取图号部分（如 图2-1-16、图七、图二六），剔除图号之后所有汉字描述；该步不依赖像素 OCR。
防错回退：仅 OCR 漏读、非报警引起缺失 → 命名回退为 原图名称_图片内序号.png
示例：
图2-1-16 M4出土铜舟、盘、圆纹饰拓片 → 图2-1-16_1_M4-2.png
图七 M1、M2出土器物 → 图七_1_M2-1.png（重名则 图七_2_...）
7.3 成图规格
背景：纯白（255,255,255）。
像素：保留原始像素，未重采样。
扫描噪点：完整保留（不进行去噪处理）。
留白：物体长宽的 2%–5% 动态留白，无固定边距。
方向：横向优先（统一旋转校正）。
比例尺：保留原始相对位置（规则 B 合并时），生成新子图时若为共享则复制一份。
说明文字：与对应器物 mask 不可分割。

7.5 功能开关与配置管理
Feature Flag 清单（P0 默认：s3_llm_confirm=true，s9_loop=true，cross_fig_merge=false，rotation_correct=true；均可独立开关以 A/B 对比）：s3_llm_confirm（S3 低置信 LLM 二次确认）、s9_loop（S9 Supervisor 闭环）、cross_fig_merge（跨图合并）、rotation_correct（纵横向旋转校正）。硬约束不在此清单、不可关。

8. 人工复核闭环
本章定义 Label Studio 预标注、双向同步、增量复核、字段级脱敏。
8.1 复核工具集成
Label Studio作为复核工具。任务模板：Image Mask Annotation。
标注工具：Brush（修改 mask）、Polygon（精细描边）、Keypoint（标注 artifact_id/seq/比例尺位置）。
预标注：系统 mask + bbox + OCR 结果 + Supervisor 诊断报告预填到标注界面。
复核字段：artifact_id 修正、seq 修正、比例尺归属修正、异常类型选择、复核备注。
DDL 迁移经 Flyway/Liquibase 管理；发布按报告划分批次天然支持灰度，新书接入先小批次灰度（≤5% 图）观察 PENDING_REVIEW 率与报警分布，无异常再放量。
8.2 数据回写机制
前向：S10 调用 LS import API；提交原图 + 预标注 + artifact_id 候选 + 异常报警码 + Supervisor 诊断报告。
后向：LS webhook 回调 review_callback API；event_id 幂等去重；3 次失败重新入队。
回写校验：mask 格式 RLE / artifact_id 格式 / seq 映射 schema 严格校验。
回灌动作：
  仅修正 mask → 状态转 VALIDATED，触发 S8 最终输出
  修正 artifact_id 或 seq → 重新调用 S3 重抽正文，再进入 Supervisor 诊断
  复核不通过 → 状态转 FAILED + failed_reason 记录
8.3 增量复核与恢复
复核通过后 FigureState 重新进入调度员管线，调度员检查复核人员修正字段，决定是否重新调用相关智能体。增量复核避免重新跑整个管线。
复核结果反哺：所有复核结果作为高质量样本进入 golden set 集合；每季度基于 golden set 重新评估 Supervisor 诊断与各智能体的准确率；如出现显著下降（>5%）触发 prompt 与参数调优流程。
8.4 字段级脱敏
考古报告涉及墓葬坐标、墓主身份等敏感信息。复核环节的安全策略：
LS 暴露面：Nginx 反向代理 + TLS 强制 + SSO 认证。
字段级脱敏：坐标类字段（prot_location, tf_coord）复核界面按需展示，专家可解锁查看。
导出限制：复核导出数据须经审批；外部复核外包需 NDA。
安全补充（§6.3）：模型网关启用鉴权与每 Worker 配额，防 GPU 被打爆；S3 对象存储定义 Bucket 访问策略（原图只读、产物写受限）；S3 LLM 二次确认对正文片段做输入截断与指令隔离，降低 Prompt 注入风险。

9.2 资源估算
按 §5.9 调用预算：16,124 图 × 单图最坏 12 次模型调用 = 193,488 次调用（其中 VLM 按 §5.9.1 单图预算核算）。
VLM 档位 B（3s/QPS 12）：4.3 小时/全量 ≈ 3 卡 GPU × 1.5 小时批次
SAM 因 mask 计算低显存：1 张图 ≤ 2s，QPS 16，630 分钟 ≈ 1 卡 GPU
OCR 离线批处理：6 核 CPU 即可
存储：原图实测约 2.4GB（压缩 jpg）；产物按 3× ≈ 7.2GB；中间 mask 按 5× ≈ 12GB（复核通过+7 天清理）。P0 可用本地磁盘/MinIO 承载，S3 10TB+ 为生产冗余预算。
数据库：30 天全量图状态 ≈ 50GB（含 JSONB 诊断历史）
9.3 批处理与并发
分批：按报告划分批次。
并发：调度员并发任务调度器；并发度 = GPU 资源 × VLM 吞吐最佳平衡点。
Claim 机制：SELECT FOR UPDATE SKIP LOCKED 或队列原子的认领机制，避免两个 worker 抢同一 figure。
断点续跑：每处理完一个 Figure 立即刷库；进程重启从最近未完成节点继续。
批次暂停：PENDING_REVIEW 阈值分报告自适应——对上游 figure-note 完整率高的报告沿用 20%；对已知高缺失率报告按该报告上游处理后预期缺失率校准阈值，避免一刀切导致批次频繁暂停。P0 先以 figure-note 完整率最高的报告（郑州商城/奉节白帝城）跑通端到端，再逐步适配高缺失率报告。

附录 A：解析规范（参考件）
第一篇：考古线图解析指导规则（图面理解与分类）
本规则旨在为考古线图的数据化处理提供图面解析、内容分类及逻辑归属的标准定义，解决“如何看懂图片”的问题。
1. 图片基础结构定义
图书结构化得到的考古报告图片自上而下（或总体分布）由三个基本结构层构成：物体线图、器物序号（可能缺失）、比例尺。
比例尺：位于图题上方、物体线图下方，提供图像与实际物理尺寸的换算关系。比例尺必须为带刻度的图形化标尺，其物理位置可能横向或纵向排版。
器物序号：对于一个图片中包括多个器物的情况，图片中会用数字标识各个器物。
物体线图：占据图片的主体区域，为单件或多件器物的考古线条绘制图及局部纹饰展开图。
2.文本基础结构定义
图题：位于整张图片的底部。它是该图的核心标识，描述了出土单位、器类等核心信息（如 图2-1-4 M4出土铜鼎）。在进入自动化处理管线前，图题经过结构化相关工作识别，可以通过XML figure-title解析获得。
图注：是图题的补充，主要包括器物的器物号和名称（如 M4:6），通过XML figure-note解析获得。
3. 核心编号概念定义
为确保系统正确处理图片内部关联与跨图片数据追溯，必须明确区分以下两类编号：
器物序号：指图片中标注于线图旁、比例尺旁或图注中的阿拉伯数字（如 1.、2.、3.）。其作用范围为当前单张图片内部，用于在同一图片内对不同器物或同一器物的不同局部视图进行区分和匹配。该序号不具备跨图片的唯一性或全局性。
器物号：指图题及图旁标注中形如 M4:2、M2:1、M4:6 的编号。其作用范围为整个考古发掘现场（或整本考古报告），是在该考古工作全域范围内唯一标识某一件具体器物的编码。该器物号用于最终输出文件的命名及跨图片、跨章节的器物数据关联与追溯。
系统在处理过程中，须严格区分“图片内序号”与“器物号”的用途：序号用于图面元素的匹配与分组；器物号用于分组判定（同号合并）及最终文件命名。
4. 图像前置分类与过滤机制（综合判定规则）
系统对图片类型的判定必须遵循 “视觉内容优先，图题描述辅助” 的二级综合判定机制：
第一步（视觉内容判定）：系统首先通过图像语义分割或目标检测预判画面主体。若画面中存在可被独立分割的器物文物线图轮廓（即具备封闭线条、器形特征），则优先进入 类型 A（器物文物类） 处理管线。
第二步（视觉内容图题关键词兜底）：仅当视觉内容判定为非器物线图，结合图题关键词（“平面图”、“墓室”、“地层”、“遗迹”等）进行否决。此类图片直接抛弃处理，不进行任何掩膜分割与重组，仅保留原始文件存档。
特别说明：对于图题含有“地层”等关键词但画面内容为清晰独立器物线图的图片（如地层出土的帽钉、掌钉等），强制归类为类型A，必须进入分割提取流程。
5. 多物体与单物体的判定及关联分组规则
在判定图片属于类型A（器物文物类）后，依据图面结构及器物号归属确立分组逻辑：
规则A（多物体图）：图注存在明确的图片内器物序号列表（如 1.、2....）。图面中相应位置存在带有相同序号的独立线图。数据匹配逻辑为“图底器物序号 ⇔ 线图旁的器物序号 ⇔ 比例尺序号”三者进行匹配绑定。
规则B（单物体图）：图面无整体序号列表，全图展示的是一件器物的多个局部展开图或不同角度的视图。
分组逻辑（以器物号为最高聚合维度）：系统提取图面中所有带有器物序号的线图及其对应的器物号（如 M4:2、M4:4）。然后按器物号进行分组聚合：
同一器物号下的所有局部视图（如 M4:2 下的序号1“舟腹部”和序号2“舟圈足”），合并为一张单物体图（规则B）输出；
不同器物号各自独立拆分为单张图片。
6. 文字、比例尺与线图的识别归属规则
说明性文字归属：存在于线图旁边的说明性文字（如“盖顶面纹饰”、“颈部”、“主视图”、“侧视”等），视为该器物多视角图组不可分割的组成部分，必须纳入掩膜的提取范围。
横纵向排版识别：比例尺和文本的OCR识别，必须同时支持横向排版（如 0 —— 6厘米）和纵向排版（如文本和图例垂直旋转90度）。
匹配依据：比例尺与器物的匹配严禁使用坐标距离算法，必须依据图面标注的具体图片内序号文本进行硬性对应（详见第二篇第4条）。

第二篇：考古线图结构化提取与切割重组规范（技术执行）
本规则定义了系统在完成图面理解后，如何执行实例分割、空间变换、信息提取及最终图像生成的工程技术标准。
1. 核心切割与掩膜标准
切割方式：严禁使用矩形框（Bounding Box）切割，必须采用基于掩膜（Mask）的实例分割技术（如 SAM、YOLOv8-seg 等），以像素级精度贴合物体轮廓进行提取。
重叠区域处理：当多个器物在视觉空间上产生重叠时，仅提取该物体自身掩膜所识别的独立像素，严禁进行像素补全。
掩膜提取范围：掩膜提取的物理范围必须完整涵盖三个部分：物体线图本身 + 线图旁的说明性文字 + 该物体使用到的专属比例尺（包括图形化比例尺及纯文字尺寸标注）。
2. 新图生成与排版标准
针对不同类型的图，执行不同的生成与合并策略：
针对多物体图（规则A）：
系统遍历每一个图片内器物序号 n.，提取对应的线图掩膜、图旁文本(如有)以及绑定的比例尺。
共享比例尺处理：如果多物体图中全图仅存在一个统一的、所有器物共享的比例尺，则系统在生成每一个序号 n. 的子图时，必须将该共享比例尺的掩膜完整复制一份，并入到每一张独立新生成的图片中，确保所有切割出的单件文物都自带度量信息。
多比例尺处理：若图面存在多个比例尺（如大比例尺和小比例尺），需根据比例尺左侧标注的图片器物序号，将该比例尺分配给对应序号的线图。
全部线图元素保持原图相对坐标不变，平移放置到新画布中，比例尺可以至于最底部。
针对单物体多局部图（规则B）：
当因“器物号相同”触发规则B合并时，该件器物的所有局部视图、所有的说明文字以及所有专属比例尺（即使是多个专属比例尺，如标注有 1、2. 0-9厘米 和 3. 0-3厘米），绝对禁止拆分，必须作为一张完整的新图进行合并和输出。
位置保留要求：图上的比例尺序号仅用于指示局部视图的测量比例，不参与图面拆解。合并时，必须原封不动地保留其原始图面上的视觉位置和方向。系统仅需对整张图进行整体的方向校正（如统一旋转至横向），校正后各元素之间的相对间距、方位关系完全保持不变，不得重新排版或集中归置比例尺。
3. 图像旋转与方向统一规范
统一旋转至横向：系统在生成新图前，必须具备姿态校正能力。如果检测到原图存在纵向排列的比例尺及对应物体，算法必须执行整体空间变换：
将专属比例尺顺时针或逆时针旋转90度，修正为标准横向排列的样式。
同一组内与比例尺绑定的物体线图及说明文字，必须采用完全相同的旋转矩阵进行同步旋转，确保最终输出的成图为统一的横向排版标准。
4. 空间匹配与异常处理（强制规则）
强制匹配逻辑（图片内序号硬性对应）：
系统通过OCR识别图面中各局部视图旁标注的序号文本、比例尺左侧标注的序号文本和解析XML figure-note得到图注中器物序号的文本（如 1.、2.）。
匹配凭证：仅以器物序号是否完全一致作为匹配的唯一标准（例如：图注 1. 对应线图旁的 1 和比例尺旁的 1）。严禁使用坐标距离、空间位置远近等算法进行关联匹配。
比例尺归属判定分级规则：系统对比例尺的归属判定，必须严格按照以下优先级顺序执行，严禁使用坐标距离算法进行推断：
一级（硬性匹配）：若OCR识别出比例尺旁存在明确的图片内器物序号文本（如“1.”、“2.”），则严格按照该器物序号文本与对应线图进行硬性绑定。
二级（全局默认共享）：若全图范围内经实例分割及OCR检测仅存在唯一一个比例尺（无论其旁是否标注序号），则该比例尺自动视为该图片的“全局默认比例尺”。在生成子图时，该比例尺掩膜必须被完整复制并分配给所有无法通过一级规则匹配到专属比例尺的线图。此情况下不得触发异常报警。
三级（异常报警）：仅当全图存在两个及以上比例尺，且其中至少一个比例尺旁未标注序号，导致系统无法通过一级硬性匹配为其分配对应线图时，触发报警，等待人工复核。
异常触发条件（必须报警）：
若通过XML figure-note解析处器物序号（如 1.），但在图面空间上找不到标注了该序号（1）的线图；
若图面存在标注了序号的线图，但XML figure-note无对应的说明文本；
若图面存在标注了序号的多个比例尺，但无法与任一线图序号对应上；
若某比例尺旁未标注任何图片内序号，且不满足上述“二级全局默认共享”条件（即存在多个比例尺），无论其物理位置如何，均不得通过距离算法进行归属推断，必须触发报警，等待人工复核确认其归属；
若图面存在多个不同器物号但图注无任何序号列表（即无序号多物体图场景），系统无法通过序号文本完成匹配，必须触发报警，等待人工复核确认归属；
若密集排列的多个器物在实例分割过程中因共享公共基准线导致切割后各器物轮廓不完整，系统无法保证独立掩膜的完整性，必须触发报警，等待人工复核。
触发上述任一情况，系统判定匹配失败，必须立即触发报警，等待人工介入复核，不得进行强制配对或猜测配对生成。
5. 最终输出与命名规则
图像规格：新生成的图像采用纯白色背景，绝对保留原始像素大小，完整保留原始图像上的印刷扫描噪点。画布四周不设固定留白，根据提取出的物体实际大小进行动态留白（建议为物体长宽的 2%-5%）。
文件命名格式：严格采用 原图名称_图片内序号_器物号.png 格式。
替换规则：器物号中的冒号 : 必须统一替换为连字符 -（例如 M4:6 → M4-6）。
原图名称取值与去重规则：
提取图题中的图号部分（如 图2-1-16、图七、图二六），剔除图号之后的所有汉字描述性内容。
后缀保留：若图号包含字母或数字子编号（如 图七a、图2-1-16b），必须完整保留该后缀，不得丢弃。
重名防冲突：若经上述提取后，同一批次处理中产生完全相同的图名字符串（如存在两张独立的 图七），系统自动在重名图号后追加序号（从 _1 开始递增，如 图七_1、图七_2），确保最终文件名全局唯一。
示例：
图2-1-16 M4出土铜舟、盘、圆纹饰拓片 → 提取为 图2-1-16，最终输出 图2-1-16_1_M4-2.png；
图七 M1、M2出土器物 → 提取为 图七，最终输出 图七_1_M2-1.png（若有另一张 图七，则第二张输出 图七_2_...）。
防错回退机制：
禁止自动回退生成。若因前置处理中无法获取到器物号，且该缺失并非由“异常报警”引起（例如OCR漏读），则命名回退为 原图名称_图片内序号.png。
特别强调：若系统已触发第二篇第4条所定义的任一“异常报警”条件（包括但不限于比例尺无法匹配、图底序号列表缺失、分割轮廓不完整等），系统必须立即暂停该图所有切割与生成流程，将该图标记为“待复核”状态，不得输出任何PNG文件。待人工介入修正匹配关系后，方可重新执行生成。
