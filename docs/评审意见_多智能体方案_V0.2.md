# 《考古报告图文 Pair 数据构造 · Supervisor-Worker 多智能体方案》评审意见

- **评审对象**：docs/考古报告图文Pair数据构造_多智能体方案_V0.1.docx、V0.2.docx（以 V0.2 为最终评审版本）
- **评审依据**：examples/ 下 21 份报告 XML 全量实测（16,124 个 imagedata、media 16,367 个文件）、本评审现场统计与抽样精读
- **评审口径**：XML 为最终结构化数据；当前 XML 属中间态、后续迭代。因此意见按"应在系统内解决 / 应写入上游契约由上游解决"区分标注。

---

## 一、总体结论

方案成熟度较高，主要优点：

1. **量化口径与实测基本一致**：16,124 个 imagedata 与实测完全一致；media 实测 2.24GB / 平均 143.4KB，与 V0.2 的"≈2.4GB / ≈143KB"吻合（总量偏高约 7%，属可接受）。V0.1"22 份报告"在 V0.2 已更正为 21 份，与 examples 实际目录数一致。
2. **工程边界清晰**：上游输入契约、硬约束不可关、双源三链降级矩阵、PENDING_REVIEW 闭环、内容合规前置否决（P1）、golden set 回归门禁，构成完整质量闭环。
3. **V0.1→V0.2 修订方向正确**：S9 必选终检与迭代开关分离、幂等键两层化（线程键不含 iteration）、Pair 多候选 Schema（candidate_images/image_merge_mode）、SAM 文字/比例尺并入掩膜的 union 算法、s3_llm_confirm 默认开启，均回应了 V0.1 的真实缺陷。

但存在 **4 个 P0 级结构性问题**（figure↔figure-note 关联规则、图题契约与命名回退、独立比例尺条图、序号硬匹配的自洽性）与 **一批 P1 级覆盖缺口**（彩板管线与 XML 实际形态脱节、拓片类未定义、表格未覆盖、图号 O/〇 归一化等），多数都能在 examples 中间态数据中找到直接反例。以下按严重级分列。

## 三、P0 级评审意见（P0 启动前必须解决）

### P0-1 figure ↔ figure-note 关联规则不成立，需要重新定义并写入上游契约

**位置**：§2.4 主链解析器、§4.1 S1。

**问题**：方案唯一给出的关联规则是"遍历文档序将 figure 与其**后紧邻**的 figure-note para 关联"。examples 中存在四类反例：

1. **图注在前、图在后**：万州瓦子坪 data.xml L5005"6. 陶三足砚（2001CWWM3：4）"位于其对应 figure（L5006）之前；L5013"1. 瓷碗（2001CWW M3：2）"同样前置。
2. **一图多注、多段注**：瓦子坪 L128–129，图四的图注被拆成两段 para；"紧邻其后"只拿第一段，第二段丢失。
3. **同图号多 figure**：瓦子坪 L108–127 两张"图四"（image9 + image10）连续出现，图注在最后一张之后——按规则第一张永远拿不到图注；大兴东庄营"图三六〇""图三七三"等同样成对重复。
4. **条状比例尺图夹在图与图注之间**：瓦子坪 image10.jpg（93×27 像素）插入两张"图四"之间，会把"器物组合图 + 其图注"的邻接关系截断。

**影响**：链①（Pair 键唯一权威源）在关联环节即发生错位/丢失，所有下游置信度与降级矩阵失效。

**建议**（双管齐下）：
- 系统内：S1 改为"双向回溯关联"——以图号为锚，图注归属"最近的同图号 figure 集合"，图注允许前置/后置/多段合并；以图注内序号集合与相邻图注的连续性做校验，校验失败入违约清单而非静默。
- 上游契约：在契约中明确"每图 figure-note 紧跟其后、多段合一、同图号多图必须每图独立携带 note 或共享声明"；把瓦子坪图版区（L5000–5044）与东庄营拓片区列为上游返工样本。

### P0-2 图题契约与命名规则之间存在断裂：图题大面积缺失、容器形态不统一、存在未契约角色

**位置**：§1.4 上游输入契约、§2.1 XML 结构、§7.2 文件命名、§4.1 S1。

**问题**：
1. **图题覆盖率远低于"标准型"假设**（见上表）：郑州商城仅 35% 的 figure 有 caption role="figure-title"。而 §7.2"原图名取值：从 XML figure-title 提取图号部分"依赖图题存在；§7.4 防错回退只覆盖"OCR 漏读导致 artifact_id 缺失"一种情形，**图题缺失无任何回退路径**，命名会直接失败。
2. **容器形态至少三种**：a) `figure > caption role="figure-title" > para`（瓦子坪、郑州商城）；b) `figure > para role="figure-title"` 无 caption 包裹（大兴东庄营 L240 等 51 处）；c) 章节级 `para role="figure-title"` 游离于 figure 之外（瓦子坪 L2570"图版七"、L5014"图版六三"位于两张图之间，充当图版标题）。
3. **未契约角色**：role="qr-caption"（郑州商城 82 处）、role="table-title"（栎阳城中 56 处）等，S1 契约校验未定义，会静默通过或误判。
4. **图题与条目列表混排**：瓦子坪 L2947–2949，图版一五的 caption 内容为"1. 陶釜（2001CWWM9：72） 2. 铜壶（2001CWWM9：7）图版一五"——条目列表在前、图版号在后，§7.2"剔除图号之后所有汉字描述"的规则不适用于此顺序。

**建议**：
- 上游契约必须明确三点：每图必有 figure-title（或明确允许缺失并给出命名回退）、容器形态唯一化（统一为 caption 包裹）、角色全集枚举（figure-title / figure-note / table-title / qr-caption / ……）。
- 系统内：S1 契约校验升级为"角色白名单 + 图题存在性 + 容器形态"三级断言；图题缺失时命名回退为 `fileref 文件名_序号_器物号.png` 并写入清单（而非 E102 整书排除，避免 35% 图题缺失的郑州商城被整体排除）。
- 图号提取规则增加"先定位图版号/图号，再剥离条目列表"的逆序处理用例。

### P0-3 比例尺存在"独立媒体文件"形态，方案的比例尺三级只覆盖"图内比例尺"

**位置**：§4.6 S6 掩膜三件套、§5.3/§5.4 比例尺三级、§4.2 S2 决策表、附录 A 第一篇 1。

**问题**：实测 155 个条状 imagedata（典型 93×27～176×24，赵廷隐 15+、唐懿德、余家河等均有），如瓦子坪 image10.jpg 以独立媒体文件形式夹在"图四"两张图之间，极可能是共享比例尺条（"0 …… 10厘米"）。方案对比例尺的处理全部假设"比例尺在该 figure 的像素内"：S2 会把条图判为 discarded（无器物轮廓）、S6 的共享复制只在单图内生效——**跨 imagedata 的比例尺归属与复制完全无定义**，导致切割后的子图丢失度量信息，直接违反"专属比例尺"硬约束。

**建议**：
- S2 决策表增加"比例尺条图/页眉条"判定类（宽高比 + 无器物轮廓 + 图内横向刻度图形），分类为 scale_strip 而非 discarded；
- 定义 scale_strip 与其服务的器物图（同图号 figure 集合）的归属规则，并明确其与"禁坐标距离"的关系（见 P0-4）；
- 若确认上游会把比例尺条合并回器物图，写入上游契约；否则本系统必须支持跨 imagedata 比例尺复制。

### P0-4 "序号硬匹配 / 严禁坐标距离"存在逻辑自相矛盾，需澄清适用范围

**位置**：§5.3 序号硬匹配、附录 A 第一篇 6、第二篇 4。

**问题**：附录 A 规定"匹配唯一凭据为序号文本完全一致，严禁使用坐标距离、空间位置远近进行关联匹配"。但**像素侧序号标注（"1."）与其对应线图 mask 之间的绑定，本质上只能是空间关系**——一张 6 器物的组合图（如瓦子坪图四），OCR 得到 6 个序号框、SAM 得到 6 个 mask，文本一致匹配无法建立"序号 1 ↔ mask A"的对应。若不澄清，规则 A 的整个执行链路（"图底序号 ⇔ 线图旁序号 ⇔ 比例尺序号"三绑定）在工程上不可实现。

**建议**：把"禁坐标距离"精确限定为两点，其余放开：
1. **文本硬匹配层**（图注 seq ↔ 像素序号文本 ↔ 比例尺旁序号文本）：仅文本一致性，禁任何距离推断——这是硬约束本意；
2. **标注↔mask 绑定层**：允许并定义"序号标注框与线图 mask 的邻接/包含判定"（标注文本 mask 与线图 mask 连通域邻接即为绑定），这是结构性关系而非距离猜测；
3. **比例尺归属层**：保持三级规则不变（有序号硬绑、单尺共享、多尺报警），明确"比例尺条图与器物图之间的跨图归属"沿用同图号集合归属（P0-3），不引入距离。

建议把上述区分写成附录 A 的修订条款，并同步更新硬约束追溯矩阵第 4、5、7 条。

## 四、P1 级评审意见（影响覆盖率与正确率）

### P1-1 彩板（图版）管线与 XML 实际形态脱节：放弃了 XML 中已存在的直接映射信号

**位置**：§4.7 S7、§1.2.3 彩板特征。

**问题**：S7 的条目→artifact_id 映射**只**从正文"（图版N，1）"引用反推 + 像素 OCR 条目号。但实测：
- 瓦子坪图版一五（L2941–2953）：条目映射直接写在 XML 里——caption 含"1. 陶釜（2001CWWM9：72） 2. 铜壶（2001CWWM9：7）"，且每条目另有独立 figure + figure-note（"4. 陶灯（2001CWWM9：71）"）。链①对彩板是**完整可用**的，S7 却绕开它去正文反推，属于无谓降级。
- "彩图都是一张"假设不成立：瓦子坪图版一五由 1 张整版图（image163）+ 6 张条目单图（image158–168）构成，一版多 figure。
- 白帝城 L882–883：图版标题是**无 role 的正文 para** 且存在粘连（"图版七 白帝庙遗址上区图版八 白帝庙遗址唐代水沟00FBG1……"一段含两个图版标题），与 §4.7"上游解析正确前提下不做版面粘连兼容"的假设直接冲突。

**建议**：
- S7 主链改为"XML figure-note/caption 直读（链①）→ 正文图版引用（链②）校验 → 像素 OCR 条目号（链③）校验"，降级矩阵与线图管线对齐；
- 一版多 figure 聚合：以图版号为聚合键把同版条目 figure 归组；
- S1 契约校验增加"图版标题粘连检测"（一段内出现 ≥2 个图版号模式），命中入违约清单。

### P1-2 拓片类图在 S2 决策表中缺失

**位置**：§4.2 S2 决策表、§1.6 术语、附录 A 第一篇 4。

**问题**：拓片是考古报告的高频图类（大兴东庄营 71 处"（拓片）"图题、栎阳城上 944、唐懿德 86、洪洞南秦 36），典型形态"图七 M3出土铜钱（拓片）"：黑白墨拓、常多枚同图、无序号、无比例尺。现有决策表会把它们归入"无可辨识主体→discarded"或"无序号多器→E005 报警"，两条路径都会丢失器物数据。方案仅在 §5.6 图注语法用例里出现一次"拓片三七"（当作图版路径），没有成体系的处理定义。

**建议**：S2 增加拓片类别（rubbing）：视觉特征（黑白反相、无色彩）+ 图题关键词"拓片"联合判定；对"多器物拓片 + 图注/正文含器物号"的图，允许按链①/链②反推分张（无序号时按 artifact_id 拆分，视作 rule_a 的无序号退化形），比例尺三级规则对拓片给出豁免或按"原大/比例说明"处理的显式条款；在 golden set 分层中补充拓片类（现 §10.2 分层没有此类）。

### P1-3 表格（登记表）完全未纳入范围声明

**位置**：全文（§2 XML 结构、§3 数据流均未提 table）。

**问题**：实测 514 张表，包括"附表一 战国墓登记表"（后屯下册）等含墓号/随葬品/尺寸列的登记表，其中部分登记表含**器物级**尺寸与描述（可作为链②文本侧来源）；table 元素还带 `html-content` 属性（整表转义 HTML 的副本），S1 若提取文本会取到双份内容造成污染。方案对表格"不处理、不排除"均未声明。

**建议**：P0 明确排除表格并在文档声明理由（登记表→墓/单位级聚合信息，非器物描述段；如需纳入留 P1+ 扩展点）；S1 解析必须显式跳过 `html-content` 属性值；把"器物级登记表"写入候选链②来源的路线图。

### P1-4 图注角色与内容不一致：描述段被标为 figure-note（长沙青振反例）

**位置**：§5.6 图注语法用例、§1.4 上游契约。

**问题**：方案 §5.6 把"三塊板的長、厚和 C1同。在这一層的 12 塊蓋板的上面……"列为"描述段而非图注"的用例，但在长沙青振 data.xml L385 中，这段文字**实际就是 role="figure-note"**。方案假设"角色正确由上游保证"，而这条用例恰恰证明上游中间态存在角色误标。类似地，大兴东庄营 L6068 出现极简图注"（M171∶1）（拓片）"（无序号、纯器物号+类型），也不在 §5.6 用例清单中。

**建议**：把这两类改为"图注内异常形态识别"用例——S3 检测"图注内含整句描述性正文/无序号结构"时路由至链②侧或入上游返工清单；用例清单补充"仅器物号无序号"形态；同时把"（M171∶1）（拓片）"式的比例冒号（∶）覆盖进 §2.2.1 归一化单测。

### P1-5 图号体系缺"〇/O/0/空格"归一化，图号提取规则存在逆序反例

**位置**：§2.3 图号编号体系、§7.2 图号提取、§4.7.1 图版号正则。

**问题**：实测"图二六O"（郑州商城 L12679，字母 O）与"图二六○"（L13036，正确）并存；瓦子坪"图版三O"（L3603）；"图 三一"（含空格，瓦子坪 L775）。方案图版号正则 `图版[一二三四五六七八九十百千0-9]+` 无法匹配"图版三O"；图号规则未定义 O/○/0 与空格的归一化。后果：图引用反推（链②）、原图名提取、图版号连续性校验都会漏配。

**建议**：归一化步骤增加：O→〇（仅图号上下文）、去除图号内部空格、全角数字；将"图二六O""图版三O""图 三一"纳入 §2.3 单测反例；图版号正则扩充 `[一二三四五六七八九十百千〇O0-9]+`。

### P1-6 P0 选书与实测完整率不符

**位置**：§9.3 批处理与并发。

**问题**：方案称"P0 先以 figure-note 完整率最高的报告（郑州商城/奉节白帝城）跑通端到端"。实测邻接图注覆盖率为：瓦子坪 92.3%、白帝城 79.2%、郑州商城 65.3%；且郑州商城图题覆盖仅 35%（P0-2），其图注形态大量依赖正文反推（如"图二六一"12 件器物全部靠"标本C11T112③：27"类锚点）。按当前中间态数据，郑州商城并非最容易跑通的报告。

**建议**：P0 选书改为"瓦子坪（图注/图题形态最完整）+ 白帝城（无空格器物号形态）"，郑州商城作为"链②反推压力测试"第二梯队；或明示"上游处理后预期完整率"口径，并给出上游修复的验收门槛数值。

### P1-7 附录 A 与 §1.2.1 对"图题/比例尺位置"的描述自相矛盾

**位置**：附录 A 第一篇 1、2 vs §1.2.1 图像像素特征。

**问题**：§1.2.1 声明像素三要素=线图+序号+比例尺、"图题在 XML 中，不在像素"；附录 A 却描述"图题位于整张图片的底部、比例尺位于图题上方、物体线图下方"。若 media 已裁掉图题，"比例尺位于图题上方"没有参照；若 media 未裁掉图题，S4"不 OCR 图题与图注"的假设需要额外处理（图题文字可能被误当说明文字并入掩膜）。

**建议**：统一为"像素元素白名单"表述（器物线图、序号、比例尺、线图旁说明文字；禁止出现图题/图注），删除附录 A 中图题像素位置的描述；并在摄入期增加"图题残留检测"（像素底部文字区与 XML figure-title 相似度校验），作为上游契约校验项。

### P1-8 内容合规验证（P1）缺少可执行的样本集与方法定义

**位置**：§11.2、§10.5 P1。

**问题**：P1 是"不达标则全部设计失效"的否决项，但方案只给出"通过率 ≥95%"与对策 A/B，未定义：合规语料样本集（人骨、人殉、殉牲、盗洞等具体样本清单与规模）、通过率的测量方法（每次调用级/每图级/每批级）、"审核豁免通道"的申请路径与时间线、自托管候选模型与 §5.9"VLM 档位 A/B/C"的对应关系及其显存/成本约束。

**建议**：P1 增加交付物清单——合规样本集（建议从 examples 全量中抽取 ≥200 条敏感语料 + 对照中性语料）、网关拦截率统计口径、自托管选型矩阵（Qwen-VL/InternVL 等 × 显存 × 通过率 × 时延），并把"审核通过率"列为 golden set 之外的独立回归指标。

## 五、P2 级评审意见（工程细节与一致性）

1. **SqliteSaver 与多 Worker 并发矛盾**（§3.4.4、§9.3）：P0 单文件 SQLite checkpointer 在"调度员 + 多 Worker 并发"下有写锁竞争；16k figure 的 checkpoint 体量与清理策略未定义。建议 P0 即启用 WAL + 按 book_id 分库，或直接 PostgresSaver（PG 已在部署拓扑中）。
2. **幂等键含三个版本号导致全量重跑**（§3.4.4、§6.5）：`UNIQUE(book_id, figure_id, rule_version, prompt_version, judge_prompt_version)` 意味着任一 prompt 变更即全量重算。需补充"版本退休 + 旧 figure_states GC"策略（§9.4 生命周期表未覆盖）。
3. **成本模型缺单价换算**（§5.9.3）：单图成本帽 2 元 × 16,124 = 3.2 万元上限，但 VLM 档位 B 的 token 单价 × 调用次数 × 5k tokens/次 的全量成本未测算。建议补全量成本表，作为选型输入。
4. **Pair 文本侧的跨章节合并未定义**（§6.1 PairRecord）：同一 artifact_id 可能存在多段 TextArtifact（正文两处描述 + 图注），`description_text: Optional[str]` 单值无法承载，拼接/去重/冲突裁决规则缺失。建议定义文本组装规则与 provenance 结构。
5. **附录 B mermaid 与 §4.7.3 矛盾**：拓扑图 S7→S10 直连，而 §4.7.3 明确"彩板路径与线图路径共享 S8 匹配组装器与 S9 Supervisor 质检"。需修正拓扑或文字。
6. **状态机命名不一致**（§6.2.1 vs §8.2）：复核回灌"仅 mask"时 §8.2 说转"VALIDATED"，状态机中无该状态（应为 ASM_VALIDATED→OUTPUT）。统一命名。
7. **S9 调用预算行表述费解**（§5.9.1）："3（迭代 × 3 节点）"应为"最多 3 轮修正诊断（每轮 1 次）+ 1 次必选终检"，并同步更正 §9.2 的最坏调用次数口径（V0.2 已改为"模型调用"而非"VLM 调用"，注意 SAM/OCR 与 VLM 的单位一致性）。
8. **E007 为占位条款**（§6.3、§12）：追溯矩阵第 13 条"七类异常报警"依赖附录 A"其他硬约束场景"，而附录 A 第二篇 4 实际只定义了六类触发条件。要么补第七条，要么把矩阵改为"六类 + 扩展位"。
9. **术语问题**：全文"彩板"应为"彩版"；"图版/拓片"并列关系未定义（拓片可按图版编号"拓片三七"，也可按图编号"图七"）；§1.2.2 图注示例与 §4.3.1 解析树中"豆（M3：4）"的序号语义（区间 vs 单号）在 name_inferred 时如何映射 seq 需要补一句说明。
10. **golden set 分层缺两个实测形态**（§10.2）：分层表中无"拓片类"（P1-2）与"条状比例尺图"（P0-3）两类，而这两类恰是当前方案风险最高的形态，建议在 100→300 扩展时强制纳入。
11. **比例尺条图的"整图旋转"联动**（§4.6.2）：纵向排版旋转时，若比例尺是独立媒体文件（P0-3），旋转矩阵的跨图同步未定义，需与 P0-3 一并解决。
